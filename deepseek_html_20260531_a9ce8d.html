1. Introducción

Este documento es tu guía definitiva, agente de desarrollo. Aquí encontrarás:

  • La especificación arquitectónica (resumida pero completa).
  • Las instrucciones para integrar x-dd desde el primer momento.
  • Los pipelines concretos que debes escribir para validar cada paso.
  • El orden de implementación de la Fase 0.

No hay ambigüedad. Cada tarea tiene un pipeline x-dd asociado. Si el pipeline falla, la tarea no está terminada.

2. La Regla de Oro (No Negociable)

📌 Nada se considera completado hasta que x-dd lo valide.
  • Cada archivo de código que escribas debe tener su correspondiente prueba en x-dd.
  • Cada funcionalidad nueva debe demostrarse con un pipeline que pase.
  • Los receipts (pruebas criptográficas) se generan automáticamente en cada ejecución exitosa.

Si x-dd no dice "PASSED", tú no has terminado.

3. Configuración Inicial (Antes de Escribir Código)

3.1. Asume que x-dd está instalado

El usuario ya tiene x-dd funcionando en su sistema. Tú solo llamarás a los comandos:

xdd /xdd-start
xdd /xdd-build
xdd /qa-review
xdd /cierre-fase

3.2. Directorio de trabajo

Crear el repositorio con esta estructura mínima inicial:

agentik/
├── agentik/
│   ├── __init__.py
│   ├── core/
│   │   └── (vacío por ahora, pero directorio creado)
│   ├── mempalace/
│   │   └── (fork vacío, se llenará en tarea 1)
│   ├── security/
│   │   └── receipts.py
│   ├── channels/
│   │   └── cli.py
│   └── __main__.py
├── tests/
│   └── pipelines/            # archivos .xdd
├── docs/
│   └── MASTER_SPEC_v5.0.md
└── pyproject.toml

3.3. Pipelines de x-dd

Crea un directorio tests/pipelines/ y dentro escribe archivos con extensión .xdd.
Cada pipeline es una secuencia de comandos x-dd que tú mismo ejecutarás para validar.

Ejemplo de pipeline mínimo (tests/pipelines/fase0_01_import_mempalace.xdd):

/xdd-start
/agentik run "from agentik.mempalace import Client; print('ok')"
/gate assert salida_contiene "ok"
/cierre-fase

4. Fase 0 — Fundación (Tareas Concretas)

A continuación, las tareas en orden estricto. Cada tarea incluye su pipeline de validación.

📦 Tarea 0.1: Fork de MemPalace

Objetivo: Tener el módulo agentik/mempalace/ con el cliente básico funcionando.

Acciones:

  1. Copiar el código de MemPalace (MIT) dentro de agentik/mempalace/.
  2. Asegurar que from agentik.mempalace import Client no da error.
  3. Configurar el directorio de datos en ~/.agentik/mempalace/.

Pipeline de validación (tests/pipelines/tarea_0.1.xdd):

/xdd-start
/agentik run "python -c 'from agentik.mempalace import Client; c=Client(); c.store(\"test\", wing=\"Test\"); print(c.recall(\"test\"))'"
/gate assert salida_contiene "test"
/cierre-fase

Criterio de éxito: El pipeline pasa y se genera un receipt en ~/.agentik/mempalace/Audit/.

⌨️ Tarea 0.2: CLI básica

Objetivo: Poder ejecutar agentik run "comando" desde la terminal.

Acciones:

  1. Implementar agentik/channels/cli.py con un comando run que reciba un string.
  2. Conectar ese comando a la ejecución real de x-dd (usando subprocess).
  3. Guardar cada ejecución en MemPalace (wing Conversations).

Pipeline de validación (tests/pipelines/tarea_0.2.xdd):

/xdd-start
/agentik run "echo 'hola mundo'"
/gate assert salida_contiene "hola mundo"
/agentik mempalace recall "hola mundo" --wing Conversations
/gate assert salida_contiene "hola mundo"
/cierre-fase

🔌 Tarea 0.3: Integración x-dd (Adapter)

Objetivo: El agente puede ejecutar pipelines completos de x-dd.

Acciones:

  1. Implementar XDDAdapter en agentik/channels/xdd_adapter.py con métodos:
    • run_pipeline(pipeline_path)
    • build()
    • qa_review()
    • close_phase()
  2. Cada método debe generar un receipt y persistirlo en MemPalace (wing Audit).

Pipeline de validación (tests/pipelines/tarea_0.3.xdd):

/xdd-start
/agentik run "from agentik.channels.xdd_adapter import XDDAdapter; a=XDDAdapter(); a.build()"
/gate assert salida_contiene "Receipt generated"
/cierre-fase

🔐 Tarea 0.4: Receipts y Seguridad

Objetivo: Cada acción importante genera un receipt HMAC.

Acciones:

  1. Implementar security/receipts.py con funciones:
    • generate_receipt(action, result) -> dict
    • verify_receipt(receipt) -> bool
  2. Usar cryptography o hashlib para HMAC-SHA256.
  3. Almacenar cada receipt en MemPalace (wing Audit).

Pipeline de validación (tests/pipelines/tarea_0.4.xdd):

/xdd-start
/agentik run "from agentik.security.receipts import generate_receipt; r=generate_receipt('test','success'); print(r['signature'])"
/gate assert salida_coincide_regex "[a-f0-9]{64}"
/cierre-fase

📊 Tarea 0.5: Observabilidad básica

Objetivo: Exponer métricas mínimas y logs estructurados.

Acciones:

  1. Configurar logging en formato JSON.
  2. Crear un endpoint interno /metrics (aunque no haya API aún, solo para pruebas internas).
  3. Registrar las métricas:
    • agentik_tasks_total
    • agentik_pipelines_total
    • agentik_receipts_total

Pipeline de validación (tests/pipelines/tarea_0.5.xdd):

/xdd-start
/agentik run "import logging; logging.info('test')"
/gate assert log_contiene "test"
/cierre-fase

5. Integración Continua con x-dd

Una vez que la Fase 0 esté completa, debes configurar un pipeline maestro que ejecute todos los pipelines de prueba cada vez que se modifique el código.

Pipeline maestro (tests/pipelines/fase0_completa.xdd):

/xdd-start
/xdd-build   # equivalente a ejecutar todas las tareas 0.1 a 0.5 en orden
/qa-review    # verifica que todos los receipts existen y son válidos
/cierre-fase

Este pipeline debe ejecutarse automáticamente (por ejemplo, con un hook de git o un scheduler). Si falla, el código no se considera válido.

6. Estructura de Receipts para Fase 0

Cada receipt debe seguir este formato:

{
  "id": "uuid-generado",
  "timestamp": "2025-01-15T10:00:00Z",
  "action": "xdd-build | xdd-start | qa-review | cierre-fase | run_command",
  "actor": "agentik",
  "result": "success | failure",
  "pipeline": "nombre_del_pipeline.xdd",
  "signature": "hmac-sha256"
}

Todos los receipts se almacenan en MemPalace, wing Audit, con retención permanente.

7. Criterios de Aceptación de la Fase 0

La Fase 0 se considera completada cuando:

  1. Todos los pipelines de las tareas 0.1 a 0.5 pasan.
  2. El pipeline maestro fase0_completa.xdd pasa.
  3. Existe al menos un receipt por cada acción significativa.
  4. Las métricas básicas son visibles (pueden ser por log).
  5. No existe código muerto ni funcionalidades de fases posteriores.
